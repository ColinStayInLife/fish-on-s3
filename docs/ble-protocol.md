# BLE 通信协议规格说明书

> FishOn-S3 竿梢子机 ↔ 主机（M5StickC Plus）BLE 通信协议
> 版本: V1.0 | 基于 BLE 4.2+ Advertising

---

## 一、通信架构

- **物理层**: BLE 4.2/5.0
- **传输方式**: BLE Advertising（广播，无连接）
- **工作频段**: 2.4GHz ISM (2402-2480MHz), 40 channels
- **广播信道**: 37/38/39 (主要) + 数据信道
- **拓扑**: 多点星形 (1 主机收, N 子机发)

```
子机 (广告者)     ← BLE 广播 →     主机 (扫描者)
  ESP32-C3                            M5StickC Plus
  NimBLE                              NimBLE (Scanner)
  ADV_NONCONN_IND                     Passive Scan
```

## 二、广播包格式

### 2.1 数据载荷 (6 bytes)

采用 **Manufacturer Specific Data** 类型 (Type 0xFF)。

```
BLE Advertising PDU (31 bytes max payload):
┌────────────────────────────────────────────────────────────────┐
│  Header(2B)  │  AdvA(6B)  │  AdvData(31B max)                │
└────────────────────────────────────────────────────────────────┘

AdvData 结构:
┌────────┬────────┬────────┬────────────────────────────────────┐
│ Length │ Type   │ Flags  │ ... more AD structs ...           │
│ (1B)   │ 0x01   │ (1B)   │                                    │
├────────┼────────┼────────┼────────────────────────────────────┤
│ Length │ Type   │ Company│ 自定义数据 (6 bytes)                │
│ 0x08   │ 0xFF   │ ID(2B) │                                    │
└────────┴────────┴────────┴────────────────────────────────────┘

自定义数据 (6 bytes):
┌────────┬────────┬────────┬────────┬────────┬────────┐
│ Byte 0 │ Byte 1 │ Byte 2 │ Byte 3 │ Byte 4 │ Byte 5 │
├────────┼────────┼────────┼────────┼────────┼────────┤
│ MAGIC  │ ROD_ID │ STATE  │ AMP_H  │ AMP_L  │ BATT   │
│ 0xA5   │ 0-15   │ 0x00-  │ msb    │ lsb    │ 0-100  │
│        │        │ 0x07   │        │        │        │
└────────┴────────┴────────┴────────┴────────┴────────┘
```

### 2.2 字段说明

| 字段 | 位置 | 范围 | 分辨率 | 说明 |
|:----|:----|:----|:------|:-----|
| MAGIC | Byte 0 | 0xA5 (固定) | — | 协议魔数，用于过滤非 FishOn 设备 |
| ROD_ID | Byte 1 | 0-15 | 1 | 竿编号，0-7 正常使用，8-15 保留 |
| STATE | Byte 2 | 0x00-0x07 | 1 | 当前鱼口状态码 |
| AMP_H | Byte 3 | 0-255 | 见下 | 幅度高位 |
| AMP_L | Byte 4 | 0-255 | 见下 | 幅度低位 |
| BATT | Byte 5 | 0-100 | 1% | 电池剩余电量百分比 |

### 2.3 状态码定义

| 代码 | 名称 | 含义 | 主机响应 |
|:----|:-----|:-----|:---------|
| 0x00 | IDLE | 待命，无活动 | 🟢 绿色状态 |
| 0x01 | SUSPECT | 疑似小鱼闹窝 | 🟡 黄色，短蜂鸣×1 |
| 0x02 | FISH_ON | 中鱼确认 | 🔴 红色，持续蜂鸣×3 |
| 0x03 | BLOW_UP | 大鱼爆口 | 🔴🔴 高频报警 |
| 0x04 | DEEP_SLEEP | 深睡（低电） | ⚫ 灰色 |
| 0x05 | ERROR | 自检错误 | 🔵 蓝色 |
| 0x06 | HEARTBEAT | 心跳包（存活） | 🟢 绿色 |
| 0xFE | PAIR_REQ | 配对请求 | 进入配对模式 |
| 0xFF | OFFLINE | 离线（主机推断） | ⚫ 灰色 |

### 2.4 幅度编码

- 16 位无符号整数 (0-65535)
- 映射 0 → 0.0g, 65535 → 16.0g
- 分辨率: 16.0/65536 ≈ 0.244 mg/LSB
- 编码: `raw = (amplitude_g / 16.0) * 65535`
- 解码: `g = raw / 65535.0 * 16.0`

## 三、通信时序

### 3.1 广播参数

| 参数 | 空闲态 | 活跃态 | 配对态 |
|:----|:------|:-------|:------|
| 广播间隔 | 5000ms | 200ms | 1000ms |
| 广播次数/事件 | 1 | 3 | 2 |
| 发射功率 | -12dBm | 0dBm | 0dBm |
| 随机延迟 | 0-10ms | 0-50ms | 0-10ms |

### 3.2 主机扫描参数

| 参数 | 值 |
|:----|:----|
| 扫描间隔 | 100ms |
| 扫描窗口 | 99ms (接近连续扫描) |
| 扫描模式 | Passive (被动扫描，不响应) |
| 重复过滤 | 关闭 (接收所有广播包) |

### 3.3 一次完整通信周期

```
子机深睡 (~10μA)
  │
  │ MPU6050 运动中断触发 (幅度 > 0.1g)
  ▼
子机唤醒 (~15ms 稳定时间)
  │
  │ 采样 2 秒数据 (100Hz, 200 样本)
  ▼
本地分析 (~5ms 计算)
  │
  │ BLE 广播 3 次 (每次 ~0.5ms 空中时间, 间隔 200ms)
  ▼
 ┌─ 振动持续 → 继续广播
 │  振动停止 → 浅睡 (每 5s 广播一次心跳)
 │  静默 > 60s → 深睡
 ▼
子机深睡 (~10μA)
```

> **注意**: 主机可能丢失部分广播包（多次广播确保至少收到一次）

## 四、配对流程

### 4.1 物理配对

```
初始化: 所有未配对的子机以 ROD_ID=0xFE 启动
        主机以 ROD_ID=0xFF (广播自己的ID)

步骤 1: 长按主机 A 键 5 秒 → 进入配对模式
步骤 2: 主机扫描，列出所有 ROD_ID=0xFE 的 MAC 地址
步骤 3: 对每个待配对的子机，短按子机上的物理按钮（或重新上电）
步骤 4: 主机为每个子机分配竿号 (0-7)，记录到 Preferences
步骤 5: 退出配对模式
```

### 4.2 软件配对包

子机配对请求:
```
Byte 0: 0xA5 (MAGIC)
Byte 1: 0xFE (PAIR_REQ)
Byte 2-5: 0x00 (reserved)
```

主机配对确认 (通过扫描时窗口的 BLE 超级帧):
> **Phase 5 实现**，Phase 1-2 先硬编码 ROD_ID。

## 五、防冲突设计

### 5.1 多子机同时广播

当 8 个子机都在 200ms 间隔广播时:
- 每子机 3 次广播/事件 × 每次 0.5ms = 1.5ms 空中时间
- 随机延迟: 每个广播叠加 0-50ms 随机延迟
- 8 个子机总负载: 8 × 3 × 0.5ms / 200ms = **6% 信道利用率**

即使同时广播，冲突概率 < 5%，且主机扫描窗口 99ms 足够捕获。

### 5.2 邻居干扰

- **魔数过滤**: 0xA5 不是常见 BLE 魔数，可过滤 99%+ 外设
- **信道隔离**: 37/38/39 三个广播信道
- **邻居白名单**: 仅在配对模式记录子机 MAC，丢弃未知设备

## 六、错误处理

| 场景 | 处理方式 |
|:----|:---------|
| 校验失败 (MAGIC 不匹配) | 丢弃 |
| 同一子机重复包 | 由主机去重（基于序列号，Phase 4+） |
| 超时未收到 (30s) | 标记为 OFFLINE，显示 ⚫ |
| 电池低于 10% | 子机进入 DEEP_SLEEP 模式 |
| IMU 读取错误 | 广播 ERROR 状态码 |
